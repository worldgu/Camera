# Camera 摄影站 — 需求文档

> 版本：v1.8  
> 日期：2026-08-17  
> 状态：进行中（实验室两个实验均已落地，后续为真实照片相关的打磨项）

---

## 一、项目定位

一个面向**刚买相机的新手**的摄影教程网站，同时作为个人摄影作品集展示。

两个核心价值：
1. **教** — 用通俗易懂的方式，让新手快速学会拍照
2. **展** — 以极简画廊的方式呈现个人摄影作品

---

## 二、目标用户

- 刚购入第一台相机的纯新手
- 有手机拍照基础，想系统学习摄影的人
- 对摄影感兴趣、想入门的潜在用户

---

## 三、视觉风格

- **极简黑白**，照片为主
- **大量留白**，文字克制，画廊感 / 仪式感
- 首屏全屏大图冲击，进入内页后保持同样的克制美学
- 教程页面在黑白基调下保证良好的阅读体验（适当的行高、字重对比）
- 首页标题 / 签名式文案走文艺路线，参考"人生如逆旅，我亦是行人"的意象（具体文案待开发时选型）
- 支持**暗色 / 亮色切换**（黑白风格下的深浅两种基调）

---

## 四、技术栈

| 项目 | 选型 | 理由 |
|------|------|------|
| 框架 | **Astro** | 内容站友好、SEO 极佳、默认零 JS、可插入交互组件 |
| 交互组件 | **React** | 用于作品瀑布流、筛选、图片查看器等动态部分 |
| 样式 | **原生 CSS** | 配合极简风格，完全自定义，减少依赖 |
| 部署 | **GitHub Pages** | 免费、自动部署、自带 HTTPS |
| 域名 | `worldgu.github.io/Camera` | 项目初期使用 GitHub Pages 子路径 |
| 语言 | 中文（i18n 结构尚未落地） | 目前文案硬编码在各页面模板中，加英文前需先做文案集中管理 |
| 统计 | **Google Analytics**（或同类） | 接入网站访问统计 |

│   ├── 曾经用过（器材回忆录）

### 5.1 首页

- 全屏大图 + 一句标题 / 签名式文案 + 几个导航按钮
- 最画廊、最有仪式感的首屏体验
- 向下滚动可有少量内容（最新作品缩略、最新教程），但克制不喧宾夺主
- 文案风格：文艺、诗词感、人生 / 行路 / 光影意象
- 首屏导航藏起来（汉堡菜单），保持画面干净

### 5.2 教程 / Learn

双入口设计：

**学习路径（Learning Path）**
- 按"从零到会拍"的学习顺序排列
- 清晰的进度感（已读 / 未读可后续加）
- 适合完全新手跟着走

**分类索引（Topics）**
- 按知识领域分类，方便查阅
- 分类包括（七大分类全部完成，已无"即将推出"占位）：
  - 基础篇：曝光三要素、对焦、测光、曝光补偿、焦距与视角、模式转盘
  - 构图篇：经典构图法、景别、画面层次
  - 光线篇：光的方向、自然光时段、人工光基础
  - 题材篇：人像、风光、街拍、静物、运动、夜景
  - 操作篇：白平衡、RAW vs JPEG、胶片模拟与色彩、对焦区域与驱动模式、清洁保养
  - 后期篇：LR 基础、调色、锐化、二次构图
  - 器材篇：相机分类、镜头体系、配件

**文章详情页**
- URL 结构：`/learn/{category}/{slug}`，如 `/learn/basics/aperture`
- 文字 + 示意图 / 图解（**当前状态**：39 篇正文，需配图的文章均已内嵌 SVG 图解，
  schema 已预留可选 `cover` 字段但未启用）
- 通俗易懂、像朋友聊天一样的语气
- 上一篇 / 下一篇导航
- 返回分类 / 返回学习路径
- 底部有社交分享按钮

### 5.3 作品 / Works

**浏览模式切换**：
- 瀑布流视图（默认）：时间线从新到旧，大图瀑布流
- 相册 / 项目视图：按项目分组展示

**筛选维度**（可切换）：
- 按题材：人像 / 风光 / 街拍 / 静物 / 其他
- 按时间：时间线瀑布流（从新到旧）
- 按项目：自定义项目分组

**列表交互**：
- **滚动加载更多**（无限滚动）
- 鼠标悬停在缩略图上**什么都不显示**（保持画面干净）
- 点击缩略图以**灯箱弹窗**形式查看大图（不离开列表页）
- 灯箱内可上下一张切换，也可跳转到照片详情页

**照片详情页**：
- URL 结构：`/works/{slug}`，如 `/works/mountain-sunset`
- 单张大图占满视觉重心
- 照片信息：相机型号、镜头、光圈、快门、ISO、拍摄地点、拍摄时间
- 一句话描述
- EXIF 信息（**当前状态**：由 `works.json` 手写维护；构建时自动提取为后续方案，见第八章）
- 上一张 / 下一张快捷浏览
- 社交分享按钮

### 5.4 装备 / Gear

**页面结构**：

- **正在用（主力装备）**
  - 相机
  - 镜头（按常用程度排序）
  - 常用配件
- **曾经用过（器材回忆录）** — 记录走过的器材路

图解写法：正文内嵌 `<figure class="diagram">` + 内联 `<svg>`，配色只用 `global.css` 里的
`dia-stroke` / `dia-stroke-thin` / `dia-fill` / `dia-fill-soft` / `dia-text` /
`dia-text-muted` / `dia-text-label` / `dia-text-invert` 这几个 class，不写死颜色值，
深浅色主题才能同时成立。

图解硬性规范（踩过坑，务必遵守）：

1. `<figure>` 与 `</figure>` 之间**不能有空行**。CommonMark 会在空行处结束 HTML 块，
   后续缩进 ≥ 4 空格的 SVG 行被当成缩进代码块，直接把源码渲染成 `<pre>`。
2. 所有 `dia-text*` 在 CSS 里是 `text-anchor: middle`。文本按左对齐坐标书写时，必须
   追加修饰类 `dia-text-start`（定义在 `global.css`，只改 `text-anchor: start`），
   否则文字会向左跑出色块甚至画布。
3. 色块内的文字要预留足够宽度，8 个中文字大约需要 104 viewBox 单位以上。
4. 底部文字与 viewBox 下边缘至少留 14 单位空白，否则渲染时被裁切。

`content.config.ts` 的 schema 已加可选 `cover` 字段（供后续封面图使用，当前未启用）。

#### 建模方案：纯 Three.js 程序化建模（方案 A，已确认）

**方案对比：**

| 方案 | 说明 | 视觉效果 | 交互友好度 | 加载体积 | 开发量 |
|------|------|----------|------------|----------|--------|

**为什么选方案 A：**

- 每个部件都是独立 Three.js 对象，点击检测、动画、状态切换天然支持
- 零外部资源依赖，git 友好，加载极快
- 后续可增量升级：先有骨架，再逐步提高精度，或替换部件为 glTF（天然向方案 C 演进）

**效果预期：**
- 风格化低面数版本，一眼可认出是 A7C2（机顶军舰部、握柄弧度、翻转屏厚度等特征）
- 按键有形状无精细刻字（模式转盘档位可用纹理贴图）
- 材质区分：哑光黑机身 + 金属机顶
- 整体感觉偏向"产品示意图"，精致但不追求照片级真实

### 10.3 曝光模拟器（/lab/simulator）

左侧控制面板，右侧实时预览画面。调节相机参数，画面即时变化。
用于直观理解曝光三要素（光圈 / 快门 / ISO）如何共同决定一张照片的样子。

#### 实现方案：2.5D 分层 + shader 后处理（方案 C，已确认）

**方案对比：**

| 方案 | 说明 | 真实感 | 焦距透视 | 开发量 | 加场景成本 | 性能 |
|------|------|--------|----------|--------|------------|------|
| A 全 3D 场景 | Three.js 建 3D 场景 | ★★★★★ 物理正确 | ★★★★★ 真实透视 | 大 | 高（需建模） | 中低 |
| B 纯 2D + shader | 单张照片 + 后处理 | ★★★ 画面质量好 | ★ 只能缩放 | 小 | 低（找图 + 深度图） | 高 |
| C 2.5D 分层 | 多层图片 + Z 轴视差 + shader | ★★★☆ 分层景深 | ★★★ 视差模拟透视 | 中 | 中低（拆图层） | 中高 |

**为什么选方案 C：**
- 核心教学价值是"理解光圈 / 快门 / ISO 对画面的影响"，这一点 2.5D 完全能胜任
  （景深虚化、亮度变化、噪点都可以用 shader 高质量实现）
- 多层视差能模拟出焦距变化的立体感，比纯 2D 缩放体验好很多
- 开发效率适中，能快速验证功能是否好用
- 加场景成本可控（拆图层即可），后续可以持续丰富场景库
- 如果后续反响好，再升级成全 3D，交互逻辑和 UI 可复用

**做不到的事（已知局限）：**
- 没有真正的自由视角（无法绕到物体侧面）
- 景深是"分层模糊"，不是物理连续变化的（仔细看有层次感，但对教学演示完全够用）
- 焦距变化是"视差 + 缩放"的近似模拟，不是严格的光学透视

#### MVP 功能范围（已确认）

**可调参数（3 个核心）：**
- **调节 UI 形式：模拟拨轮（方案 B，已确认）** — 外观是相机拨轮/拨盘的样式，
  操作方式为点击 +/- 按钮或鼠标滚轮调节数值。兼顾相机的视觉质感与操作的直观性。
- **光圈** f/1.4 ~ f/22 — 影响景深虚化程度 + 进光量（亮度）
- **快门速度** 1/4000s ~ 30s — 影响运动模糊 + 进光量（亮度）
- **ISO** 100 ~ 25600 — 影响画面亮度 + 噪点颗粒感

**视觉效果：**
- **亮度变化** — 三参数共同决定曝光值，实时响应
- **景深虚化** — 光圈越大背景越虚，基于分层深度的 shader 模糊
- **噪点颗粒** — ISO 越高颗粒越粗，胶片颗粒 shader
- **运动模糊（MVP 必做，已确认）** — 快门越慢拖影越长，场景中包含运动元素
  （如流水、行人、车流等），用 shader 沿运动方向做模糊，直观展示快门速度对
  动态物体的影响

**场景预设（2-3 个）：**
- 人像 — 人物主体 + 背景环境，方便看景深效果
- 风光 — 前景 / 中景 / 远景多层纵深，看整体清晰度变化
- 夜景 — 暗光环境，看 ISO 噪点和慢门效果

**场景图片来源：免费素材图（已确认）**

- 从 Unsplash、Pexels 等免费图库中挑选合适的照片
- 挑选标准：构图清晰、主体明确、有足够前后景层次（方便做分层景深）
- 每个场景需拆分为 3-5 个图层（前景 / 中景主体 / 中景环境 / 远景 / 天空等）
- 运动场景额外需要运动元素的独立图层（用于运动模糊效果）

**辅助功能：**
- **自动曝光开关（已确认启用）** — 打开后调整任一参数，其他参数自动补偿，
  保持整体曝光不变。
  补偿逻辑：
  - 调节光圈 → 快门速度自动对应变化（光圈开大 1 档，快门加快 1 档）
  - 调节快门速度 → 光圈自动对应变化
  - 调节 ISO → 光圈自动对应变化（ISO 升高 1 档，光圈缩小 1 档）
  教学价值：直观展示"曝光三要素的跷跷板关系"——三参数此消彼长，共同决定曝光量
- **实时直方图（MVP 必做，已确认）** — 预览区下方显示亮度直方图（256 级灰阶分布），
  辅助理解曝光分布。过曝 / 欠曝时直方图特征一目了然。

#### 后续可扩展
- 焦距调节（广角 / 标准 / 长焦）
- 曝光补偿（±3EV）
- 测光模式（评价 / 中央重点 / 点测光）
- 更多场景（静物 / 街拍 / 运动）
- 参数预设快捷按钮（"人像模式""风光模式""夜景模式"一键套用）
- 保存 / 分享当前参数组合

### 10.4 视觉与交互规范

**视觉风格延续：**
- 极简黑白基调，与全站统一
- 3D 场景深色背景 + 柔和布光，保持画廊感
- 控制面板使用现有 UI 语言（同字体、同间距、同交互样式）
- 支持深浅色主题 — 3D 场景背景光、面板背景自动适配

**响应式：**
- 桌面端：左控制面板 + 右预览区 / 3D 场景，横向布局
- 平板 / 手机：上下布局，控制面板可折叠，预览区优先

**性能考量：**
- 首屏不加载 Three.js，进入实验室页面才按需加载
- 场景资源（图片 / 分层图）按需加载，切换场景时再拉取
- 移动端降低后处理精度，保证流畅

### 10.5 技术选型

| 项目 | 选型 | 说明 |
|------|------|------|
| 3D 引擎 | **three.js** | 最成熟的 WebGL 库，生态完善 |
| 相机建模 | 纯程序化（Three.js 基础几何体） | 方案 A，已确认 |
| 曝光模拟器 | 2.5D 分层 + 自定义 shader | 方案 C，已确认 |

### 10.6 与教程的联动设计

**双向跳转：**
