# Camera 摄影站 — 需求文档

> 版本：v1.2  
> 日期：2026-08-13  
> 状态：已确认

---

## 一、项目定位

一个面向**刚买相机的新手**的摄影教程网站，同时作为个人摄影作品集展示。

两个核心价值：
1. **教** — 用通俗易懂的方式，让新手快速学会拍照
2. **展** — 以极简画廊的方式呈现个人摄影作品

---

## 二、目标用户

- 刚购入第一台相机的纯新手
- 有手机拍照基础，想系统学习摄影的人
- 对摄影感兴趣、想入门的潜在用户

---

## 三、视觉风格

- **极简黑白**，照片为主
- **大量留白**，文字克制，画廊感 / 仪式感
- 首屏全屏大图冲击，进入内页后保持同样的克制美学
- 教程页面在黑白基调下保证良好的阅读体验（适当的行高、字重对比）
- 首页标题 / 签名式文案走文艺路线，参考"人生如逆旅，我亦是行人"的意象（具体文案待开发时选型）
- 支持**暗色 / 亮色切换**（黑白风格下的深浅两种基调）

---

## 四、技术栈

| 项目 | 选型 | 理由 |
|------|------|------|
| 框架 | **Astro** | 内容站友好、SEO 极佳、默认零 JS、可插入交互组件 |
| 交互组件 | **React** | 用于作品瀑布流、筛选、图片查看器等动态部分 |
| 样式 | **原生 CSS** | 配合极简风格，完全自定义，减少依赖 |
| 部署 | **GitHub Pages** | 免费、自动部署、自带 HTTPS |
| 域名 | `worldgu.github.io/Camera` | 项目初期使用 GitHub Pages 子路径 |
| 语言 | 中文（结构预留双语扩展能力） | 先做中文，文案统一管理，方便后续加英文 |
| 统计 | **Google Analytics**（或同类） | 接入网站访问统计 |

## 五、页面结构

```
首页 / Home
├── 教程 / Learn
│   ├── 学习路径（Learning Path） — 按入门→进阶→实战的顺序阅读
│   └── 分类索引（Topics） — 按知识领域分类查阅
│       └── 文章详情页  /learn/basics/aperture
├── 作品 / Works
│   ├── 瀑布流视图（默认） — 从新到旧时间线，可切换筛选维度
│   ├── 相册/项目视图 — 按组浏览
│   └── 照片详情 /works/photo-title（支持灯箱弹窗快速查看）
├── 装备 / Gear
│   ├── 正在用（主力装备）
│   ├── 曾经用过（器材回忆录）
│   ├── 愿望清单
│   └── 器材详情 — 该器材下的作品列表
└── 关于 / About
```

### 5.1 首页

- 全屏大图 + 一句标题 / 签名式文案 + 几个导航按钮
- 最画廊、最有仪式感的首屏体验
- 向下滚动可有少量内容（最新作品缩略、最新教程），但克制不喧宾夺主
- 文案风格：文艺、诗词感、人生 / 行路 / 光影意象
- 首屏导航藏起来（汉堡菜单），保持画面干净

### 5.2 教程 / Learn

双入口设计：

**学习路径（Learning Path）**
- 按"从零到会拍"的学习顺序排列
- 清晰的进度感（已读 / 未读可后续加）
- 适合完全新手跟着走

**分类索引（Topics）**
- 按知识领域分类，方便查阅
- 分类包括（第一版先做基础篇，其余留占位）：
  - 基础篇：曝光三要素、对焦、测光、曝光补偿、焦距与视角、模式转盘
  - 构图篇：经典构图法、景别、画面层次
  - 光线篇：光的方向、自然光时段、人工光基础
  - 题材篇：人像、风光、街拍、静物、运动、夜景
  - 操作篇：白平衡、胶片模拟、RAW vs JPEG、相机保养
  - 后期篇：LR 基础、调色、锐化、二次构图
  - 器材篇：相机分类、镜头体系、配件

**文章详情页**
- URL 结构：`/learn/{category}/{slug}`，如 `/learn/basics/aperture`
- 文字 + 示意图 / 图解（第一版可先用占位图）
- 通俗易懂、像朋友聊天一样的语气
- 上一篇 / 下一篇导航
- 返回分类 / 返回学习路径
- 底部有社交分享按钮

### 5.3 作品 / Works

**浏览模式切换**：
- 瀑布流视图（默认）：时间线从新到旧，大图瀑布流
- 相册 / 项目视图：按项目分组展示

**筛选维度**（可切换）：
- 按题材：人像 / 风光 / 街拍 / 静物 / 其他
- 按时间：时间线瀑布流（从新到旧）
- 按项目：自定义项目分组

**列表交互**：
- **滚动加载更多**（无限滚动）
- 鼠标悬停在缩略图上**什么都不显示**（保持画面干净）
- 点击缩略图以**灯箱弹窗**形式查看大图（不离开列表页）
- 灯箱内可上下一张切换，也可跳转到照片详情页

**照片详情页**：
- URL 结构：`/works/{slug}`，如 `/works/mountain-sunset`
- 单张大图占满视觉重心
- 照片信息：相机型号、镜头、光圈、快门、ISO、拍摄地点、拍摄时间
- 一句话描述
- EXIF 信息在构建时自动提取并保存（不是实时读取）
- 上一张 / 下一张快捷浏览
- 社交分享按钮

### 5.4 装备 / Gear

**页面结构**：

- **正在用（主力装备）**
  - 相机
  - 镜头（按常用程度排序）
  - 常用配件
- **曾经用过（器材回忆录）** — 记录走过的器材路
- **愿望清单** — 种草清单

**每件器材卡片**：

- 器材大图（产品图或定妆照）
- 名称 / 型号
- 类别标签
- 入手时间（可选）
- 使用感受（一两句话：为什么买、喜欢什么、槽点是什么）
- 用它拍的作品（缩略图小网格，点击跳转）
- 主要参数（折叠展开，不默认显示，避免信息过载）
  - 相机：传感器尺寸、像素、卡口
  - 镜头：焦段、最大光圈、滤镜口径、重量
  - 配件：品牌、型号、规格

**器材分类体系**：

| 大类 | 子类 |
|------|------|
| 相机 | 微单 / 单反 / 卡片 / 胶片 |
| 镜头 | 定焦 / 变焦 / 特殊（微距、鱼眼、移轴） |
| 稳定 | 三脚架 / 云台 / 稳定器 / 独脚架 |
| 灯光 | 闪光灯 / 常亮灯 / 柔光附件 / 色片 |
| 滤镜 | ND / GND / CPL / 渐变 / 特效 |
| 存储与供电 | 存储卡 / 读卡器 / 电池 / 充电器 |
| 包与其他 | 摄影包 / 肩带 / 清洁用品 / 其他配件 |

### 5.5 关于 / About

- 个人简介
- 摄影经历 / 理念
- 联系方式（可选）

## 六、内容规划

### 6.1 教程内容

- **内容来源**：AI 基于公开摄影知识体系原创写作，组织成通俗易懂的中文教程
- **语气风格**：像朋友聊天一样，不端着，用大白话讲清楚
- **配图风格**：示意图 / 图解为主（第一版可用占位图，后续补）
- **第一版完成范围**：基础篇全部写完，包括：
  1. 开篇：你好，欢迎拿起相机
  2. 曝光三要素：光圈、快门、ISO（可拆 3 篇或 1 篇大章）
  3. 测光模式：评价 / 中央重点 / 点测光
  4. 曝光补偿：让照片变亮或变暗的小机关
  5. 对焦：AF-S / AF-C / MF，对焦点怎么选
  6. 焦距与视角：广角、标准、长焦分别怎么用
  7. 模式转盘：P / A / S / M 档，什么时候用什么

- **后续版本**：构图篇、光线篇、题材篇等逐批补上（第一版先搭好分类框架，显示"即将推出"）

### 6.2 作品内容

- 第一版使用**占位图**搭建完整结构和交互
- 作品数据用结构化数据管理（JSON / Markdown frontmatter），后续替换真实图片即可
- **图片存储**：先存放在 git 仓库中（图片数量不多的前提下），后期如超限再迁移至图床
- EXIF 信息：GitHub 构建时自动扫描新图、提取 EXIF、写入元数据，前端展示时直接读取

## 八、数据与内容管理

### 教程文章
- 格式：Markdown + frontmatter（标题、分类、发布日期、封面图、标签、slug 等）
- URL：`/learn/{category}/{slug}`
- 目录结构：`src/content/learn/` 下按分类文件夹组织

### 作品数据
- 格式：JSON 数据文件 + 图片文件
- URL：`/works/{slug}`
- 每条作品数据包含：id、slug、标题、图片路径、缩略图路径、题材、项目、拍摄时间、地点、相机、镜头、光圈、快门、ISO、描述
- 目录结构：`src/content/works/` 或 `public/works/`
- 图片存储：仓库内存储（第一版）

### 装备数据
- 格式：JSON 或 Markdown frontmatter
- 每条器材数据包含：id、名称、型号、大类、子类、状态（在用 / 曾用 / 愿望）、图片、入手时间、使用感受、参数、关联作品 id 列表

### EXIF 自动提取
- **方式**：GitHub Actions 构建时自动扫描新增图片，提取 EXIF 信息
- 提取后写入作品元数据文件，前端展示时直接读取
- 避免前端加载原图读取 EXIF 导致的性能问题
- 工具：使用 `exiftool` 或 Node.js exif 库

## 九、部署方案

- 平台：GitHub Pages
- 方式：GitHub Actions 自动构建部署
- 路径：`worldgu.github.io/Camera/`（子路径部署，需配置 Astro 的 `base` 路径）
- 触发：推送到 main 分支自动构建部署
- 构建流程：
  1. checkout 代码
  2. 安装依赖
  3. 扫描新增作品图，提取 EXIF 并更新元数据
  4. Astro build
  5. 部署到 GitHub Pages
