# Camera 摄影站 — 需求文档

> 版本：v1.5  
> 日期：2026-08-16  
> 状态：已确认（功能清单已按代码实况校正）

---

## 一、项目定位

一个面向**刚买相机的新手**的摄影教程网站，同时作为个人摄影作品集展示。

两个核心价值：
1. **教** — 用通俗易懂的方式，让新手快速学会拍照
2. **展** — 以极简画廊的方式呈现个人摄影作品

---

## 二、目标用户

- 刚购入第一台相机的纯新手
- 有手机拍照基础，想系统学习摄影的人
- 对摄影感兴趣、想入门的潜在用户

---

## 三、视觉风格

- **极简黑白**，照片为主
- **大量留白**，文字克制，画廊感 / 仪式感
- 首屏全屏大图冲击，进入内页后保持同样的克制美学
- 教程页面在黑白基调下保证良好的阅读体验（适当的行高、字重对比）
- 首页标题 / 签名式文案走文艺路线，参考"人生如逆旅，我亦是行人"的意象（具体文案待开发时选型）
- 支持**暗色 / 亮色切换**（黑白风格下的深浅两种基调）

---

## 四、技术栈

| 项目 | 选型 | 理由 |
|------|------|------|
| 框架 | **Astro** | 内容站友好、SEO 极佳、默认零 JS、可插入交互组件 |
| 交互组件 | **React** | 用于作品瀑布流、筛选、图片查看器等动态部分 |
| 样式 | **原生 CSS** | 配合极简风格，完全自定义，减少依赖 |
| 部署 | **GitHub Pages** | 免费、自动部署、自带 HTTPS |
| 域名 | `worldgu.github.io/Camera` | 项目初期使用 GitHub Pages 子路径 |
| 语言 | 中文（i18n 结构尚未落地） | 目前文案硬编码在各页面模板中，加英文前需先做文案集中管理 |
| 统计 | **Google Analytics**（或同类） | 接入网站访问统计 |

## 五、页面结构

```
首页 / Home
├── 教程 / Learn
│   ├── 学习路径（Learning Path） — 按入门→进阶→实战的顺序阅读
│   └── 分类索引（Topics） — 按知识领域分类查阅
│       └── 文章详情页  /learn/basics/aperture
├── 作品 / Works
│   ├── 瀑布流视图（默认） — 从新到旧时间线，可切换筛选维度
│   ├── 相册/项目视图 — 按组浏览
│   └── 照片详情 /works/photo-title（支持灯箱弹窗快速查看）
├── 装备 / Gear
│   ├── 正在用（主力装备）
│   ├── 曾经用过（器材回忆录）
│   ├── 愿望清单
│   └── 器材详情 — 该器材下的作品列表
└── 关于 / About
```

### 5.1 首页

- 全屏大图 + 一句标题 / 签名式文案 + 几个导航按钮
- 最画廊、最有仪式感的首屏体验
- 向下滚动可有少量内容（最新作品缩略、最新教程），但克制不喧宾夺主
- 文案风格：文艺、诗词感、人生 / 行路 / 光影意象
- 首屏导航藏起来（汉堡菜单），保持画面干净

### 5.2 教程 / Learn

双入口设计：

**学习路径（Learning Path）**
- 按"从零到会拍"的学习顺序排列
- 清晰的进度感（已读 / 未读可后续加）
- 适合完全新手跟着走

**分类索引（Topics）**
- 按知识领域分类，方便查阅
- 分类包括（七大分类全部完成，已无"即将推出"占位）：
  - 基础篇：曝光三要素、对焦、测光、曝光补偿、焦距与视角、模式转盘
  - 构图篇：经典构图法、景别、画面层次
  - 光线篇：光的方向、自然光时段、人工光基础
  - 题材篇：人像、风光、街拍、静物、运动、夜景
  - 操作篇：白平衡、RAW vs JPEG、胶片模拟与色彩、对焦区域与驱动模式、清洁保养
  - 后期篇：LR 基础、调色、锐化、二次构图
  - 器材篇：相机分类、镜头体系、配件

**文章详情页**
- URL 结构：`/learn/{category}/{slug}`，如 `/learn/basics/aperture`
- 文字 + 示意图 / 图解（**当前状态**：39 篇正文，需配图的文章均已内嵌 SVG 图解，
  schema 已预留可选 `cover` 字段但未启用）
- 通俗易懂、像朋友聊天一样的语气
- 上一篇 / 下一篇导航
- 返回分类 / 返回学习路径
- 底部有社交分享按钮

### 5.3 作品 / Works

**浏览模式切换**：
- 瀑布流视图（默认）：时间线从新到旧，大图瀑布流
- 相册 / 项目视图：按项目分组展示

**筛选维度**（可切换）：
- 按题材：人像 / 风光 / 街拍 / 静物 / 其他
- 按时间：时间线瀑布流（从新到旧）
- 按项目：自定义项目分组

**列表交互**：
- **滚动加载更多**（无限滚动）
- 鼠标悬停在缩略图上**什么都不显示**（保持画面干净）
- 点击缩略图以**灯箱弹窗**形式查看大图（不离开列表页）
- 灯箱内可上下一张切换，也可跳转到照片详情页

**照片详情页**：
- URL 结构：`/works/{slug}`，如 `/works/mountain-sunset`
- 单张大图占满视觉重心
- 照片信息：相机型号、镜头、光圈、快门、ISO、拍摄地点、拍摄时间
- 一句话描述
- EXIF 信息（**当前状态**：由 `works.json` 手写维护；构建时自动提取为后续方案，见第八章）
- 上一张 / 下一张快捷浏览
- 社交分享按钮

### 5.4 装备 / Gear

**页面结构**：

- **正在用（主力装备）**
  - 相机
  - 镜头（按常用程度排序）
  - 常用配件
- **曾经用过（器材回忆录）** — 记录走过的器材路
- **愿望清单** — 种草清单

**每件器材卡片**：

- 器材大图（产品图或定妆照）
- 名称 / 型号
- 类别标签
- 入手时间（可选）
- 使用感受（一两句话：为什么买、喜欢什么、槽点是什么）

- 主要参数（折叠展开，不默认显示，避免信息过载）
  - 相机：传感器尺寸、像素、卡口
  - 镜头：焦段、最大光圈、滤镜口径、重量
  - 配件：品牌、型号、规格

图解写法：正文内嵌 `<figure class="diagram">` + 内联 `<svg>`，配色只用 `global.css` 里的
`dia-stroke` / `dia-stroke-thin` / `dia-fill` / `dia-fill-soft` / `dia-text` /
`dia-text-muted` / `dia-text-label` / `dia-text-invert` 这几个 class，不写死颜色值，
深浅色主题才能同时成立。

图解硬性规范（踩过坑，务必遵守）：

1. `<figure>` 与 `</figure>` 之间**不能有空行**。CommonMark 会在空行处结束 HTML 块，
   后续缩进 ≥ 4 空格的 SVG 行被当成缩进代码块，直接把源码渲染成 `<pre>`。
2. 所有 `dia-text*` 在 CSS 里是 `text-anchor: middle`。文本按左对齐坐标书写时，必须
   追加修饰类 `dia-text-start`（定义在 `global.css`，只改 `text-anchor: start`），
   否则文字会向左跑出色块甚至画布。
3. 色块内的文字要预留足够宽度，8 个中文字大约需要 104 viewBox 单位以上。
4. 底部文字与 viewBox 下边缘至少留 14 单位空白，否则渲染时被裁切。

`content.config.ts` 的 schema 已加可选 `cover` 字段（供后续封面图使用，当前未启用）。

## 八、数据与内容管理

### 教程文章
- 格式：Markdown + frontmatter
- 当前 schema（`src/content.config.ts`）：`title`、`description`、`category`、`order`、`date`、
  `tags`，以及可选 `cover`（已加，暂未有文章使用）
- 正文图解直接内嵌 SVG，不走 frontmatter，写法见 6.3
- URL：`/learn/{category}/{slug}`
- slug 由文件名去掉数字序号前缀生成，统一走 `src/utils/slug.ts` 的 `slugOf()`
- 目录结构：`src/content/learn/` 下按分类文件夹组织

### 作品数据
- 格式：JSON 数据文件（`src/data/works.json`，12 条）
- URL：`/works/{slug}`
- 当前字段：id、slug、title、category、project、date、location、camera、lens、
  aperture、shutter、iso、focalLength、description、color、aspectRatio
- `color` 是 CSS 渐变占位色，替换真实照片时改为图片路径字段
- 图片存储：仓库内存储（第一版）

### 装备数据
- 格式：JSON（`src/data/gear.json`，17 件）
- 当前字段：id、slug、name、model、type、subtype、status、acquiredAt、color、review、specs
- 关联作品不存 id 列表，而是用 `matchCamera` / `matchLens` 按机身 / 镜头名反查 works.json，
  逻辑在 `src/utils/gear.ts`；配件类器材不设匹配字段，即不关联作品

### EXIF 自动提取（后续方案，尚未实现）
- **当前做法**：EXIF 字段在 `works.json` 里手写维护
- **方式**：GitHub Actions 构建时自动扫描新增图片，提取 EXIF 信息
- 提取后写入作品元数据文件，前端展示时直接读取
- 避免前端加载原图读取 EXIF 导致的性能问题
- 工具：使用 `exiftool` 或 Node.js exif 库
- **前置条件**：需要有真实照片，占位数据阶段做这个没有意义
